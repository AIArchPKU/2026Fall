## 1. 五级流水线 CPU（50 分）

### 背景知识

处理器执行一条指令时，通常需要完成取指（IF）、译码（ID）、执行（EX）、访存（MEM）和写回（WB）。流水线让不同指令的这些阶段重叠，从而提高吞吐率；数据依赖、分支和存储器访问则可能引入停顿或冲刷。前馈可以减少部分数据依赖造成的等待，但也会增加数据通路和控制逻辑。

本实验以这五个阶段及顶层连接模块作为设计起点。内部微架构由你决定，可以采用单指令在途、流水线、前馈或其他实现，在满足统一接口并通过全部测试后，探索面积与平均 CPI 的取舍。

### 任务介绍

课程提供以下六个模块的 IO 模板，内部实现由你与 AI 完整编写：

| 文件 | 对应功能 |
| --- | --- |
| `verilog/if_stage.v` | 取指 |
| `verilog/id_stage.v` | 译码与寄存器读取 |
| `verilog/ex_stage.v` | 运算、地址计算与分支判断 |
| `verilog/mem_stage.v` | 数据访存 |
| `verilog/wb_stage.v` | 写回 |
| `verilog/pipeline.v` | 顶层连接与控制 |

保留顶层模块 `pipeline` 的全部端口及其含义。内部阶段可以增加控制端口和辅助模块；新增 RTL 文件须加入 `dse/rtl.f`，仿真和综合共同读取该清单。各阶段调试端口按所选微架构提供观察信息，不参与正确性判定；提交接口必须保持规定的含义。

使用给定的 `regfile.v`、`icache.v`、`cachemem.v`。不要修改这些支持模块、指令定义、外部存储器模型、公开测试程序、Testbench 或 `golden_result`。

### 指令与接口约定

采用 Alpha 教学指令子集：32 位指令、64 位数据与地址、32 个 64 位寄存器，`r31` 恒为零。主要指令包括整数加减、乘法、逻辑、移位、比较、`LDA/LDQ/STQ`、整数条件分支、`BR/BSR/JMP/JSR/RET` 和 `call_pal` 停止。具体编码以 `sys_defs.vh` 和公开程序为准，不要求实现头文件列出的全部扩展指令。

运算保留 64 位结果。ALU literal 零扩展 8 位，访存位移符号扩展 16 位，分支位移符号扩展 21 位后左移 2 位。复位后从 PC=0 执行；顺序取指时 PC 每次递增 4，外部存储器按 8 字节对齐访问。外部存储器采用给定的 64 KiB、4 周期延迟模型。

顶层主要接口如下；完整端口名称、方向与位宽见 `pipeline.v`：

| 接口 | 含义 |
| --- | --- |
| `clock`、`reset` | 时钟与复位 |
| `proc2mem_command`、`proc2mem_addr`、`proc2mem_data` | 向外部存储器发出的命令、地址和写数据 |
| `mem2proc_response`、`mem2proc_data`、`mem2proc_tag` | 存储器事务接受响应、返回数据和返回标签 |
| `pipeline_completed_insts` | 本周期提交指令数，取 0 或 1 |
| `pipeline_commit_NPC` | 提交指令的 PC+4 |
| `pipeline_commit_wr_en`、`pipeline_commit_wr_idx`、`pipeline_commit_wr_data` | 提交指令的寄存器写回使能、目标寄存器和数据 |
| `pipeline_error_status` | 程序结束或错误状态 |

存储器事务的接受响应与读数据返回标签含义不同，请结合 `testbench/mem.v` 理解握手。HALT 应作为一条提交指令报告后停止；非法指令不提交，通过状态端口报告。部分公开程序预期以非法指令结束，测试入口会按各程序的预期状态验收。

### 面积与平均 CPI 的设计空间探索

每个程序的 `CPI = cycles / instructions`。周期从复位释放后的第一个上升沿统计到报告结束状态的上升沿；指令数为与给定预期结果一致的提交记录数，包含 HALT，不包含导致非法指令结束的指令。

全套性能指标为 56 个程序各自 CPI 的算术平均：

```text
mean_CPI = (CPI_1 + CPI_2 + ... + CPI_56) / 56
```

各程序等权，不能用“总周期数 ÷ 总指令数”替代。只有全部 56 个程序通过，才产生可用于比较的平均 CPI。

全量通过后，把控制台给出的本次 `summary.json` 路径传给综合入口。例如，将下面的示例路径替换为实际运行路径：

```sh
make dse SIM_SUMMARY=build/实际的仿真目录/summary.json DSE_ARGS='--name baseline'
```

工具检查仿真结果与当前 RTL、测试环境是否一致，并将面积和平均 CPI 关联保存。修改 RTL 后，应重新仿真和综合；单例或旧实现的测试结果不能作为新配置的性能依据。

统一使用 GPDK045 教学库和 **30 ns 理想时钟**。面积为 CPU 核标准单元面积，包含实际使用的寄存器文件和指令缓存逻辑，不包含外部存储器模型。只将 `eligible=true` 的结果纳入比较，即同一实现通过全部测试且满足统一时序目标。

尝试改变指令执行的重叠方式、前馈、冒险处理或运算资源共享等设计，记录各配置的面积、平均 CPI 和时序结果。在报告中解释性能变化的来源，以及额外硬件是否带来相应收益。具体综合条件和结果文件见 `DSE_AREA.md`。

## 2. 卷积加速核（50 分）

二维卷积是神经网络中的常见计算，由大量输入与权重的乘加组成。硬件设计可以通过并行乘加、流水线和数据复用提高吞吐率，也需要为运算单元、缓冲和控制逻辑付出面积。

不同数据流选择让输入、权重或部分和驻留在本地，以减少重复搬运。你可以采用 Input Stationary、Weight Stationary、Output Stationary、脉动阵列、Winograd 或自定义方案（比如ref文件夹中的三篇论文）；计算并行度、缓冲组织和流水结构均由你决定。随包 `ref/` 提供相关阅读材料。

### 任务介绍

在 `src/conv_accel.v` 中实现参数化的二维卷积加速核。模板提供顶层模块 `conv_accel` 的参数和端口，输入与权重缓冲、乘加逻辑、计算调度和输出控制由你与 AI 编写。

保留顶层模块名称、给定参数名及全部端口。可以添加内部模块；新增 RTL 文件须同时加入仿真清单 `run/conv.f` 和综合清单 `dse/rtl.f`。公开 Testbench 保持原样。

### 计算规则

每次 `start` 启动一帧，输入尺寸为 `IN_H × IN_W × IN_C`，权重尺寸为 `OUT_C × K_H × K_W × IN_C`。采用二维互相关计算，不翻转卷积核。

```text
OUT_H = floor((IN_H + 2*PAD - K_H) / STRIDE) + 1
OUT_W = floor((IN_W + 2*PAD - K_W) / STRIDE) + 1

Y[oy][ox][oc] = 对所有 (ky, kx, ic) 求和：
    X[oy*STRIDE + ky - PAD][ox*STRIDE + kx - PAD][ic]
    * W[oc][ky][kx][ic]
```

越界输入取零。输入和权重为有符号 8 位二进制补码，输出为精确的有符号 32 位乘加结果，不加偏置、激活、截断或饱和。

| 参数 | 默认值 | 含义 |
| --- | --- | --- |
| `IN_H`、`IN_W` | 5、6 | 输入高度、宽度 |
| `IN_C`、`OUT_C` | 2、3 | 输入、输出通道数 |
| `K_H`、`K_W` | 3、3 | 卷积核高度、宽度 |
| `STRIDE` | 1 | 步幅 |
| `PAD` | 1 | 四侧补零宽度 |

功能参数在实例化时确定，实现应支持公开用例中的参数变化，不能只针对默认尺寸编写。参数合法范围与具体数值约定见 `README.md`。

### 输入输出接口

| 端口 | 方向与位宽 | 含义 |
| --- | --- | --- |
| `clk` | 输入，1 bit | 上升沿时钟 |
| `rst_n` | 输入，1 bit | 低有效同步复位 |
| `load_we`、`load_sel` | 输入，各 1 bit | 装载使能；选择输入张量或权重 |
| `load_addr` | 输入，16 bit | 元素地址 |
| `load_data` | 输入，signed 8 bit | 装载数据 |
| `start` | 输入，1 bit | 空闲时启动一帧，一周期脉冲 |
| `busy` | 输出，1 bit | 正在处理一帧 |
| `out_valid`、`out_ready` | 输出/输入，各 1 bit | 结果有效与下游接收握手 |
| `out_data` | 输出，signed 32 bit | 当前结果 |
| `done` | 输出，1 bit | 最后一个结果被接收后的一周期完成脉冲 |

输入按 `[y][x][ic]`、权重按 `[oc][ky][kx][ic]` 顺序线性编址，最后一维变化最快；输出顺序为 `[oy][ox][oc]`，输出通道变化最快。空闲时支持按有效地址乱序装载和覆盖写入，具体地址公式见 `README.md`。

在 `busy=0` 的上升沿接受 `start`；忙碌期间忽略新的 `start` 和装载。仅在 `out_valid=1` 且 `out_ready=1` 的上升沿传输结果。`out_valid` 的拉高不能依赖 `out_ready`；当 `out_valid=1` 且 `out_ready=0` 时，保持 `out_valid=1` 且 `out_data` 不变，直到握手或复位。结果之间允许有空拍。

最后一个输出被接收后，`busy` 拉低并产生单周期 `done`。支持不复位连续处理多帧；输入与权重保持到对应地址被覆盖。同步复位应取消当前帧并清除控制状态。详细握手和复位行为以 `README.md` 为准。

### 面积与平均周期的设计空间探索

每个候选配置先通过全量功能测试，再执行：

```sh
python3 dse/dse.py run --name baseline
```

也可用 `make dse`。该入口只执行综合，不会自动运行功能测试。

性能 benchmark 固定为 **C09 第 1 帧、C10 第 1 帧和第 2 帧**。三帧尺寸相同、数据不同，计算期间 `out_ready=1`。从接受 `start` 的上升沿记为第 0 拍，统计到最后一次输出握手；不计装载、复位和帧间空闲时间。读取全量日志中的三条 `[FRAME]` 记录，计算：

```text
平均周期数 = (C09 第1帧周期数 + C10 第1帧周期数 + C10 第2帧周期数) / 3
```

综合使用 GPDK045 教学库、**10 ns 理想时钟**和固定的 benchmark 功能规模：`IN_H=5, IN_W=6, IN_C=2, OUT_C=3, K_H=3, K_W=3, STRIDE=1, PAD=1`。面积包含计算、控制及用触发器实现的缓冲。只有功能全量通过且满足统一时序目标的配置，才纳入比较。

可以探索每周期并行乘积数、输出通道并行度、累加结构、流水级数或缓冲与复用方式。若使用 `--param` 指定自行添加的架构参数，要注意它只覆盖综合参数，不会传给 `make vcs` 或 `make xrun`；仿真和综合必须对应同一配置。具体方法见 `DSE_AREA.md`。

## 设计探索与报告

在上述两个任务当中，你可以各自挑选几个自己感兴趣的设计方案或参数配置进行设计空间探索，测量面积与性能的变化，并分析其中的原因和取舍。

CPU 比较“面积、平均 CPI”，卷积核比较“面积、平均周期数”，两项均越小越好。对于同一实验，如果另一个有效配置两项均不大于当前配置，且至少一项更小，则当前配置被支配；未被其他有效配置支配的配置构成你所探索样本中的 Pareto 前沿。

在报告中整理各配置的设计差异、功能通过情况、面积、性能和时序结果，并说明变化的原因。保持每个实验内部的测试、综合边界、库和约束一致，不改变功能规模或计算精度来降低测量值。保留各配置对应的源码或可复现参数，以及相应日志和汇总结果。

报告应包含两部分的设计思路、关键接口及时序说明、AI 生成与修改过程、全量测试结果、必要的调试波形，以及设计空间探索和取舍分析。
